# Звіт з лабораторної роботи №1

## 1. Тема, номер і варіант
* **Тема:** Розробка базового консольного застосунку, збірка за допомогою Maven та налаштування CI/CD.
* **Студент:** Богуш, Національний університет «Львівська політехніка»
* **Предметна область (Варіант 3):** Розклад занять (обробка записів про аудиторії та тривалість).
* **Операційна система розробки:** Windows 11.

## 2. Мета роботи
Опанувати базові конструкції мови Java для роботи з файлами, рядками та колекціями. Налаштувати інфраструктуру проєкту за допомогою системи збірки Maven, інтегрувати статичний аналіз коду та реалізувати повний цикл безперервної інтеграції (CI) за допомогою GitHub Actions. 

## 3. Постановка задачі
Створити консольну програму, яка читає CSV-файл із записами розкладу занять.
* **Формат запису:** 5 полів, розділених `;`.
* **Чотири показники варіанта:**
  1. Кількість коректних записів.
  2. Найменший номер аудиторії.
  3. Найдовше заняття (хв).
  4. Сумарна тривалість усіх валідних занять (хв).

## 4. Структура програми
* **Пакети та файли:** Код розміщено у пакеті `ua.lpnu.kzp`. Головний файл — `Main.java`.
* **Потік даних:** 
  1. Зчитування шляхів з аргументів командного рядка (`--input`, `--output`).
  2. Завантаження рядків із файлу в пам'ять (явне вказування `UTF-8`).
  3. Валідація кожного рядка у циклі (перевірка на кількість полів, порожнечу, від'ємні значення).
  4. Обчислення метрик для валідних рядків; збереження помилок у список.
  5. Формування єдиного рядка звіту (через `StringBuilder`) та його вивід у консоль і запис у вихідний файл.

## 5. Інфраструктура
* **Система збірки:** Maven (використовується `pom.xml` та `mvnw`).
* **Залежності:** Підключено `junit-jupiter` для подальшого написання модульних тестів.
* **Аналізатор:** Налаштовано `spotbugs-maven-plugin` (версія 4.9.7.0), який запускається автоматично у фазі `verify`.
* **Пакування:** Використано `maven-shade-plugin` для створення `fat-jar` (виконуваного архіву з усіма залежностями).
* **CI/CD:** Налаштовано GitHub Actions (`ci.yml`) для паралельної збірки на 3 операційних системах та збереження `jar` як артефакту.

## 11. Відповіді на контрольні питання

1. **Яке призначення файла pom.xml?**  
Це головний конфігураційний файл проєкту Maven. У ньому записані версія програми, підключені бібліотеки (наприклад, JUnit) та налаштування плагінів (SpotBugs, Shade).

2. **Чим відрізняються фази test, verify і package у Maven?**  
`test` запускає модульні тести; `package` запаковує скомпільований код у готовий `.jar` архів; `verify` виконує додаткові жорсткі перевірки (наприклад, статичний аналіз коду) перед тим, як підтвердити успішність збірки.

3. **Навіщо потрібен Maven Wrapper?**  
Щоб будь-хто (або сервер GitHub Actions) міг зібрати проєкт без необхідності самостійно завантажувати та встановлювати Maven на свій комп'ютер.

4. **Яку роль відіграє метод main?**  
Це стартова точка програми. З нього починається виконання всього коду при запуску.

5. **Чим примітивний тип відрізняється від String?**  
Примітивні типи (`int`, `double`) зберігають лише саме значення в пам'яті. `String` — це повноцінний об'єкт, який має власні вбудовані методи для роботи з текстом.

6. **Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?**  
Тому що при діленні цілого числа на ціле дробова частина просто відкидається. Щоб отримати точне значення (з десятими), потрібно, щоб хоча б одне з чисел було типу `double`.

7. **Що станеться, якщо Integer.parseInt отримати рядок "abc"?**  
Програма викине виняток `NumberFormatException`, оскільки букви неможливо перетворити на математичне число.

8. **Чому не можна мовчки пропускати рядок із помилкою?**  
Щоб користувач не подумав, що програма обробила всі 100% даних. Він має знати, які саме рядки були проігноровані і чому, щоб мати змогу виправити вхідний файл.

9. **Як String.split(";", -1) обробляє порожнє останнє поле?**  
Параметр `-1` змушує метод зберігати порожні поля в кінці як порожні рядки (`""`). Без нього метод просто відкинув би останні порожні колонки.

10. **Чому для шляхів краще використовувати Path.of, а не "data\\input.csv"?**  
Тому що `Path.of` автоматично підставляє правильні слеші для тієї операційної системи, на якій запущено код (на Windows це `\`, а на Linux/macOS — `/`).

11. **Навіщо явно задавати StandardCharsets.UTF_8?**  
Щоб текст (наприклад, українські літери) читався і записувався правильно на будь-якому комп'ютері, незалежно від системної мови пристрою.

12. **Чим %n відрізняється від \n у форматованому виводі?**  
`%n` — це платформонезалежний перенос рядка. Він сам вирішує, що підставити: `\r\n` для Windows або `\n` для Linux/macOS.

13. **Які дані потрібно перевірити у вашому варіанті?**  
Потрібно перевірити, чи рядок має рівно 5 колонок, чи не порожні перші три текстові поля, і чи є останні два поля (номер аудиторії та тривалість) додатними цілими числами.

14. **Які тести виявлять помилку в обчисленні середнього?**  
Тести, де сума не ділиться націло на кількість (наприклад, сума 10, кількість 3). Вони одразу покажуть, чи програма не "з'їдає" дробову частину.

15. **Яке призначення статичного аналізатора?**  
Він сканує написаний код до його запуску і шукає приховані баги, вразливості або погані практики (наприклад, можливість звернення до `null`).

16. **Яку роль виконує GitHub Actions?**  
Це сервер автоматизації, який самостійно збирає код, проганяє тести та перевіряє аналізатором на трьох різних ОС кожного разу, коли ми відправляємо оновлення на GitHub.

17. **Що має містити GitHub Issue на дефект?**  
Опис того, що сталося (суть помилки), за яких умов вона виникає і як програма повинна була б працювати насправді.

18. **Що Ви повинні вказати у розділі звіту про академічну доброчесність?**  
Чесно описати, які інструменти ШІ використовувались, у якій ролі, які промпти задавались та підтвердити, що я повністю розумію весь згенерований або виправлений код.

19. **Яку роботу виконує агент DevOps, а яку – агент Валідатор?**  
DevOps допомагає налаштувати інфраструктуру, систему збірки (Maven) та пайплайни CI/CD. Валідатор перевіряє код на відповідність стандартам і шукає логічні помилки (аналог SpotBugs).

20. **Який рядок вашої програми найскладніше пояснити і чому?**  
Найскладніше пояснити логіку безпечного створення директорій перед записом у файл (рядки з `outDir.resolve` та перевіркою `Files.exists`). Довелося неочевидним чином розділити ініціалізацію папки і файлу, щоб обійти сувору вимогу аналізатора SpotBugs щодо можливого `NullPointerException` від методу `getParent()`.

# Звіт з лабораторної роботи №2

**1. Тема, номер і варіант.**

**2. Мета роботи.** 
Перебудувати предметну частину продукту з лабораторної роботи № 1: замість рядків і паралельних змінних використати власні класи, перевірку стану об'єктів, record для незмінного допоміжного значення та тести, які підтверджують збереження поведінки. Досягнуто 3-го (повного) рівня.

**3. Стан до і після цієї роботи.** 
До виконання роботи рядки формату CSV розбиралися безпосередньо у циклі `for` за допомогою `line.split(";")`. Для підрахунку загального часу та пошуку екстремумів використовувалися примітивні паралельні змінні. 
Після роботи: розбір рядка замінено викликом статичного фабричного методу `Lesson.fromCsv()`, а результати пакуються в об'єкт `RoomDuration`.

**4. Клас-сутність.** 
Створено клас `Lesson` з інкапсульованим станом (всі поля `private final`). У конструкторі реалізовано перевірку інваріантів: текстові поля перевіряються через `Objects.requireNonNull` та `isBlank()`, а числові (аудиторія та тривалість) мають бути > 0. Метод `toString()` перевизначено для форматованого виводу через `Locale.ROOT`.

**5. Фабричний метод і record.** 
Метод `Lesson.fromCsv(String line)` відповідає за розбір рядка, перевірку кількості полів (має бути 5) та конвертацію типів. Усі перехоплені помилки (`NumberFormatException`) обгортаються в `IllegalArgumentException`. Для збереження фінальної статистики створено record `RoomDuration`, який автоматично генерує геттери, `equals`, `hashCode` та `toString`.

**6. Тестування.** 
Додано `LessonTest.java` (JUnit 5) за схемою AAA (Arrange - Act - Assert). Реалізовано позитивні тести (створення коректного об'єкта), негативні (відхилення від'ємної аудиторії в конструкторі, відхилення тексту замість числа у `fromCsv`) та перевірку рівності значень record (`recordUsesValueEquality`). Всі тести з першої роботи також проходять успішно.

## 15. Відповіді на контрольні питання (вибірково)
1. **Чим потік відрізняється від колекції?** Колекція зберігає дані в пам'яті, а потік — це лише конвеєр для опису обчислень над даними; він їх не зберігає.
2. **Чому проміжні операції ліниві?** Вони не виконуються, поки не буде викликана кінцева (terminal) операція. Це дозволяє оптимізувати обробку (наприклад, при `limit`).
3. **Чим map відрізняється від mapToDouble?** `map` повертає об'єктний потік (Stream<T>), а `mapToDouble` перетворює елементи на примітивний тип `double` (DoubleStream), уникаючи зайвого пакування об'єктів.
4. **Як утворюється складений компаратор?** Шляхом виклику методів за ланцюжком: `Comparator.comparing(...).thenComparing(...)`.
5. **Яку проблему розв'язує Optional?** Він змушує розробника явно обробити ситуацію, коли результат пошуку може бути відсутнім (уникаючи `NullPointerException`).
